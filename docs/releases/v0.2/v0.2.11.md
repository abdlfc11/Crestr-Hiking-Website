# Release Notes: v0.2.11

This introduces changes included in the following PRs:

- [#102](https://github.com/abdlfc11/Crestr-Hiking-App/pull/102)
- [#103](https://github.com/abdlfc11/Crestr-Hiking-App/pull/103)

## Summary
- Improved developer experience by making Caddy domain routing environment-driven via a new `SITE_DOMAIN` variable (so the same Docker setup works for both local development and production)
-  Added robust client-side route caching for both auto-generated and manual routes -> Users who attempt to save while unauthenticated now keep their work and can restore it after logging in
- Added UI polish (smaller routing panel, tokenised styles, nav-rail border updates) and map-fitting improvements when loading cached routes.

## Changes

### Caddy automatic routing via SITE_DOMAIN ([#102](https://github.com/abdlfc11/Crestr-Hiking-App/pull/102))
- Introduced a `SITE_DOMAIN` environment variable (default `http://localhost` in example.env) so the same Caddy configuration works for both development and production.
- Updated `Caddyfile` to use `{$SITE_DOMAIN}` instead of a hardcoded production hostname.
- Wired environment loading into the Caddy service in `docker-compose.yml`.
- Later refined (in #103) to use a dedicated `caddy.env` so only the required variable is passed to Caddy (avoids leaking app/database credentials).

### Route caching, DX & UI polish ([#103](https://github.com/abdlfc11/Crestr-Hiking-App/pull/103))
- Added client-side caching of auto-generated routes after an unauthenticated save attempt, so the route survives login/registration.
- Added equivalent caching + loading support for manual routes (including coordinate restoration and start/end population).
- Replaced hardcoded padding values in `view.fit()` calls with a constant 
- Reduced the size of the main routing panel.
- Tokenised `map.css` and `stats-panel.css`.
- Updated nav-rail border styling.
- Cleaned up an overly long comment in `donate-modal.css`.
- Added a dedicated “load last route” modal with richer route details.
- Created `caddy.env` and pointed the Caddy service at it.

## Why this matters
- Environment-driven Caddy routing removes the need to edit the Caddyfile when switching between local and production, improving contributor and deployment DX.
- Route caching after failed (unauthenticated) saves prevents users from losing work and creates a smoother “save → prompt to log in → restore” flow for both auto and manual routes.
- Smaller panel, tokenised styles and improved map fitting make the UI cleaner and more consistent while keeping the map view sensible when restoring a previous route.
