## Summary

Introduced interactive SVG pin markers for start and end points (including drag-to-regenerate behaviour),
standardised coordinate handling so the UI shows [Lat, Lon], the API uses [Lon, Lat],
and the map stays in Web Mercator, 
replaced the dedicated Report Issue page with an in-map modal,
added a self-contained Privacy Policy page (with Cookie Policy),
unified SVG pin styling (green start / red end) across automatic, manual and loaded routes,
and modernised toast notifications to support success, info, warning and error states with theme-aware design.

## Changes

### Interactive start/end markers ([#79](https://github.com/abdlfc11/Crestr-Hiking-App/pull/79))
- Added `createPoint()`, `addStartEndPoint()` and `setUpPointInteraction()` helpers so start and end coordinates appear as draggable SVG pins.
- Moving either pin automatically regenerates the route when both endpoints are present.
- Coordinate entry fields now create/update the corresponding map markers and trigger path generation.
- Fixed IntegrityError handling for duplicate point names, coordinate parsing utilities, layer z-ordering and projection order bugs.

### Coordinate system standardisation ([#82](https://github.com/abdlfc11/Crestr-Hiking-App/pull/82))
- All user-facing coordinates are now displayed as [Lat, Lon].
- All frontend to backend payloads use [Lon, Lat] (WGS84).
- OpenLayers map, point and route features remain in Web Mercator ([X, Y]).
- Centralised conversion helpers (`toLonLat` / `fromLonLat`) and added validation that rejects obvious Web Mercator values with a clear error message.
- Backward-compatibility: Routes and Points saved as Web Mercator are converted to WGS84 on load.

### Report Issue modal ([#84](https://github.com/abdlfc11/Crestr-Hiking-App/pull/84))
- Removed the dedicated `/report-an-issue` page, template and stylesheet.
- Added an in-map modal (title + description) with validation, submission and success/error handling.
- Updated `showError`/`showToast` to accept an optional modal container so toasts appear correctly inside dialogs.
- Improved error-toast styling for light/dark themes.

### Dedicated Privacy Policy page ([#86](https://github.com/abdlfc11/Crestr-Hiking-App/pull/86))
- Added self-contained `privacy-policy.html`, CSS and JS (no shared tokens or imports).
- Includes full Privacy Policy + Cookie Policy content and light/dark/system theme toggle.
- Updated all in-app links (register page, map attribution, etc.) to point to the new local route.
- Removed the unused report-an-issue FastAPI route (only the viewing function, the FastAPI route which adds issues to the database is still present).

### Consistent SVG pins for all route types ([#87](https://github.com/abdlfc11/Crestr-Hiking-App/pull/87))
- Manual routing and loaded routes now use the same SVG pin markers previously reserved for automatic routing.
- Start pin colour changed to green, end pin colour changed to red for clearer visual distinction.

### Modern multi-status toasts ([#90](https://github.com/abdlfc11/Crestr-Hiking-App/pull/90))
- Renamed `showError()` to `showToast(message, type, modal)` supporting `error`, `success`, `info` and `warning`.
- Redesigned toast appearance (theme tokens, dark-mode support, dismiss controls, progress animation).
- Migrated all previous error call-sites (auth, import, routing, saved points, report-issue, validation, search) to the new API.

## Why this matters

- Interactive green/red pins make start and end points unmistakable and allow quick route adjustments by dragging.
- Standard Lat/Lon coordinates match everyday mapping conventions and eliminate a long-standing source of user confusion.
- Keeping issue reporting inside the map and providing an in-app Privacy Policy improve UX and reduce context switching.
- Unified pin styling and modern, status-aware toasts give the whole application a more polished, consistent feel.
