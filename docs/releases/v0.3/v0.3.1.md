# Release Notes: v0.3.1

This introduces changes included in the following PRs:

- [#127](https://github.com/abdlfc11/Crestr-Hiking-App/pull/127)
- [#129](https://github.com/abdlfc11/Crestr-Hiking-App/pull/129)

## Summary

- Refactored the client-side JavaScript codebase to TypeScript, improving type safety, maintainability, and the structure of shared application types
- Reorganised application initialisation and removed legacy routing behaviour, while fixing several issues around theme handling, cached routes, and route-generation event listeners
- Improved the in-app tour by allowing users to exit early, displaying tour progress, and correcting inconsistent tour button styling

## Changes

### JavaScript to TypeScript refactor ([#127](https://github.com/abdlfc11/Crestr-Hiking-App/pull/127))

- Refactored the JavaScript codebase to TypeScript to provide stronger type checking and improve maintainability
- Reorganised application initialisation alongside several smaller cleanup changes
- Moved the `LoadedRouteStats` interface out of `app.d.ts` and into a dedicated route types file
- Added `null` to the return type of `saveAppSettingsToServer()` so its type accurately represents possible outcomes
- Reverted unrelated README changes to keep the refactor focused

### In-app tour improvements ([#129](https://github.com/abdlfc11/Crestr-Hiking-App/pull/129))

- Added the ability for users to exit an in-progress tour
- Added progress information to tour popups so users can see how far through the tour they are
- Replaced incorrect CSS variables and values used by tour buttons
- Replaced the hard-coded/main theme colour reference with the correct CSS variable for improved theme consistency

## Why this matters

- Moving the frontend to TypeScript makes incorrect assumptions about application state, function return values, and shared data structures easier to catch during development rather than at runtime.
- Reorganising initialisation and removing legacy cached-route behaviour reduces technical debt left behind by previous routing changes and gives the frontend a clearer lifecycle.
- Fixes to theme handling, route restoration, and the Generate Route listener address smaller regressions that could otherwise lead to inconsistent or broken UI behaviour.
- Allowing users to leave the in-app tour gives them control over onboarding, while progress indicators make longer tours easier to follow.
